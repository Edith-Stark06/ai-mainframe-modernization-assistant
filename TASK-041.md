# TASK-041 — Golden File Tests

## Objective

Implement a golden-file testing framework that verifies the complete Java output generated by the compiler. Each COBOL fixture should have an expected Java output ("golden file"), allowing the compiler to detect even small unintended changes in generated code.

---

## Background

The compiler currently has:

- Unit tests
- End-to-end integration tests
- Regression tests

Regression tests currently validate generated Java using expected constructs.

This task introduces exact output verification through golden files.

---

# Scope

Create a golden-file testing framework that compares generated Java source code against expected Java files.

```
COBOL Source
      ↓
Compiler Pipeline
      ↓
Generated Java
      ↓
Compare
      ↓
Golden Java File
```

---

# Functional Requirements

## 1. Create Golden Test Structure

Create:

```
tests/golden/
```

---

## 2. Golden Fixture Organization

Organize fixtures as pairs.

Example:

```
tests/golden/

hello_world.cbl
hello_world.java

move_display.cbl
move_display.java

arithmetic.cbl
arithmetic.java

if_else.cbl
if_else.java

perform_until.cbl
perform_until.java

call.cbl
call.java

combined_program.cbl
combined_program.java
```

Each `.cbl` file must have a matching expected `.java` file.

---

## 3. Golden Test Runner

Implement automatic discovery of fixture pairs.

For each pair:

1. Read COBOL source.
2. Execute the full compiler pipeline.
3. Generate Java.
4. Compare generated output against the golden file.

---

## 4. Output Comparison

Normalize before comparison:

- trailing whitespace
- line endings
- final newline

Do **not** ignore:

- indentation
- ordering
- formatting
- generated statements

The comparison should fail when generated Java differs structurally.

---

## 5. Failure Reporting

When a mismatch occurs, report:

- fixture name
- first differing line
- expected output
- actual output

Failure messages should make debugging straightforward.

---

## 6. Updating Golden Files

Provide helper utilities or documentation describing how golden files should be updated intentionally after legitimate compiler improvements.

Golden files should **never** update automatically during test execution.

---

## 7. Deterministic Output

Running the compiler multiple times on the same input must always produce identical Java output.
